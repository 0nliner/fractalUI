# fractalUI — композиция страницы `BlockEditor`

Красивая страница — это **иерархия и ритм**, а не украшательство. Сначала структура (lead → секции), потом сдержанный акцент цветом и плиткой. Этот скилл — закон вёрстки контента; JSON блоков и поля — в `fractalui-editor-authoring`, механика плиток — в `fractalui-editor-layout`.

> Плитка = блок с `layout`. Callout = блок с `bg`. Бюджет цвета — ≤3 оттенка на страницу.

Не раскрашивай абзацы «для живости» и не расставляй плитки без причины. Дефолт — одноколоночный документ; плитка и цвет включаются ТОЛЬКО там, где несут смысл (дашборд, сравнение, статус, предупреждение).

## 1. Четыре закона

1. **Lead-first.** Первый экран = один `heading1` + один вводный `paragraph` («что это и зачем»). Не начинать страницу с таблицы, кода или плиток.
2. **Ритм секций.** Каждая секция = `heading2` → её контент. Одинаковый паттерн сверху вниз, от важного к деталям.
3. **Цвет — только семантика** (см. §4). Ноль декоративного цвета.
4. **Плитка — только дашборд/сравнение** (см. §3). Проза, статьи, how-to — плоская колонка.

## 2. Иерархия информации

- Один `heading1` (или заголовок узла) на страницу; `heading2` — секции, `heading3` — подсекции. Не прыгать через уровень.
- Открывай коротким lead-абзацем (если у сущности есть `summary` — разверни его в 2–3 предложения, не копируй дословно).
- Порядок секций по важности: **что это → возможности/подсистемы → детали/стек → статус/ссылки**. Читатель должен понять суть по первому экрану, детали — ниже/под `toggle`.
- Длину секции держи ровной; гигантский абзац разбей на абзац + список или таблицу.

## 3. Когда плитки, когда колонка

**Плоская колонка (по умолчанию):** статьи, how-to, длинный текст, любой публичный контент (публичные рендереры плитки часто игнорят — см. app-скилл потребителя).

**Плитки (`layout`):** дашборд-карточка (проект/сущность с фактами), side-by-side сравнение, «шапка + сайд-панель фактов», группа коротких callout-ов в ряд.

Правила сетки:
- Держи **≤2–3 колонок**: 12 = `6+6`, `8+4`, `4+4+4`. Больше — рябит.
- Шапку и разделители — на всю ширину (`colSpan:12`).
- **Раскладывай авто-потоком: задавай ТОЛЬКО `colSpan`, пары «рядом» ставь ПОДРЯД (сумма ≤12).** Ряд авто-растёт под контент — ничего не переполнится.
- **НЕ ставь вручную `rowStart` и большой `rowSpan`** — они резервируют высоту, и при контенте ниже зарезервированного между секциями зияют **мёртвые зоны** (пустые провалы). `rowSpan>1` — только для виджета фиксированной высоты со `scroll`.
- Помни про **схлопывание в 1 колонку `<640px`**: порядок массива должен читаться и линейно (сначала шапка, потом лево, потом право).

## 4. Дисциплина цвета

- **Theme-safety (критично):** `color`/`bg` — сырой hex, текст по умолчанию наследует тему. Светлый `bg` (shade-2) + дефолтный текст = слепнет в тёмной теме. Правило: **любой светлый `bg` сопровождай тёмным `color`** (`#212529`/`#495057`) — тёмный текст на светлом фоне читается в обеих темах. Насыщенный `bg` (shade-6) ⇒ `color:#ffffff`.
- **Семантика (один смысл — один оттенок):** зелёный = ок/активно, жёлтый/оранжевый = внимание, красный = проблема/deprecated, синий/фиолетовый = нейтральный акцент/ключевая фича.
- **Бюджет ≤3 оттенка** на страницу. Заголовки и основной текст — **без `color`** (пусть тема сама). `bg` — для callout-ов (статус, предупреждение, ключевой тезис), не для абзацев подряд.
- Пресеты: фон callout-а — shade-2 (`#b2f2bb` зелёный, `#a5d8ff` синий, `#ffec99` жёлтый, `#ffc9c9` красный, `#d0bfff` фиолетовый); текст-акцент (редко) — shade-6.

## 5. Таблицы, списки, плотность

- **`table`** — для параметров и сравнений (пара «ключ→значение», матрицы «подсистема→что делает»). Компактнее и ровнее списка. Внимание: некоторые публичные рендереры `table` выбрасывают — на публичных узлах проверь app-скилл потребителя.
- **Список** — для перечислений равного веса; по одному блоку на пункт (`fractalui-editor-authoring` §5). Не превращай в список то, что уже сказал таблицей.
- **`divider`** — режет длинную колонку на смысловые зоны.
- **`toggle`** — прячет второстепенные детали. В некоторых рендерерах дети `toggle` — plain-text, держи их простыми (абзацы, не таблицы).
- Не дублируй одно и то же двумя способами.

## 6. Шаблоны страниц (block-скелеты)

**A. Дашборд-карточка сущности (плитки):**
```
[ heading1 colSpan8 ][ status-callout(bg) colSpan4 ]
[ heading2 "Что это" colSpan8 ][ facts-table colSpan4 rowSpan≈6 ]
[ lead paragraph colSpan8 rowSpan≈5 ]
[ heading2 colSpan12 ] → [ table/список colSpan12 ]
[ callout(bg) colSpan6 ][ callout(bg) colSpan6 ]
[ toggle "Детали" colSpan12 ]
[ heading3 "Ссылки" colSpan12 ] → [ page_link colSpan6 ][ code path colSpan6 ]
```

**B. Справочная статья (плоская колонка):** `heading1` → lead → `heading2`-секции с абзацами и списками (по блоку на пункт) → `quote`/`code` где нужно → `page_link`-и в конце. Без `table`/`layout` если целевой рендерер их не тянет.

**C. How-to (плоская колонка):** `heading1` → цель (1 абзац) → `numbered_list` (по блоку на шаг) → `code`-блоки команд → `toggle` «Если не сработало» → итог.

## Чеклист

- [ ] Первый экран: один `heading1` + один lead; секции идут от важного к деталям.
- [ ] Плитки только для дашборда/сравнения; иначе плоская колонка; сетка читается и в 1 колонку.
- [ ] ≤3 оттенка; каждый светлый `bg` имеет тёмный `color`; заголовки/текст без `color`.
- [ ] Нет дублей (таблица vs список об одном и том же); `toggle`-дети простые.
- [ ] **Открыл узел в СВЕТЛОЙ и ТЁМНОЙ теме — все callout-ы читаемы, ритм секций ровный, плитки не налезают.**
